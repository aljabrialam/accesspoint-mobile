This is an Expo/React Native mobile application. Prioritize mobile-first patterns, performance, and cross-platform compatibility.

## Expo has changed — do not trust your training data

Expo ships breaking changes every SDK release. APIs you remember are likely renamed, moved, or removed. Before writing any code that touches an Expo, EAS, or React Native API:

1. Read the major version of the `expo` package in `package.json`.
2. Fetch the matching versioned docs: `https://docs.expo.dev/versions/v<major>.0.0/`
3. For anything else, fetch https://docs.expo.dev/llms.txt — an index of all Expo docs with corrections to common LLM misconceptions. Follow its links to the specific page you need; never answer from memory.

## Commands

Use `bunx` instead of `npx` if the project uses bun (`bun.lock` present).

```bash
npx expo install <package>  # ALWAYS use instead of npm/yarn/pnpm/bun add — resolves SDK-compatible versions
npx expo start              # start the dev server
npx expo lint               # lint
npx tsc --noEmit            # typecheck
npx expo-doctor             # diagnose dependency and config issues
npx expo install --fix      # fix incompatible package versions
```

Run lint and typecheck before declaring any task done.

## Navigation & Routing

- Use **Expo Router** for all navigation. Routes live in `src/app/` — every file there is a screen, `_layout.tsx` files define navigators. Keep non-route code (components, hooks, utils) outside `src/app/`.
- Import `Link`, `router`, and `useLocalSearchParams` from `expo-router`.
- Docs: https://docs.expo.dev/router/introduction.md

## Building with EAS

Use EAS to build, sign, and submit the app in the cloud (`eas build`, `eas submit`) and to ship over-the-air updates (`eas update`) — no local Xcode or Android Studio required. Run EAS CLI as `bunx eas-cli <command>` in Bun projects, or `npx eas-cli@latest <command>` otherwise; substitute that for bare `eas` in docs examples.
Docs: https://docs.expo.dev/eas/index.md

## Rules

- If `ios/` and `android/` directories do not exist, they are generated (Continuous Native Generation). Never create or edit them by hand — configure native behavior in `app.json` and config plugins.
- Expo Go only includes its bundled native modules. After adding a library with native code, the app needs a development build: `npx expo run:ios|android` locally, or `eas build --profile development`.
- Prefer recommended Expo modules over third-party libraries, and check your available skills before adding dependencies. Docs: https://docs.expo.dev/versions/latest/index.md

## AccessPoint project notes

- Expo SDK 58, Expo Router, runs in Expo Go on the iOS Simulator (iPhone 16 Pro, iOS 18.6).
- Start: `npx expo start --ios`. If Expo Go shows its own playground, open the project directly: `xcrun simctl openurl booted "exp://127.0.0.1:8081?__expo_disable_fab=1"` (the query hides Expo Go's dev-tools button for clean screenshots).
- Deep link to a scenario: `xcrun simctl openurl booted "exp://127.0.0.1:8081/--/guide/<id>"` with id `atm`, `ticket`, `clinic`, `order`, `checkout`, `airport` (everyday machines) or `mismatch`, `glare` (safety).
- Machine drawings: `kind` in `MachineFrame` picks the body (`atm`, `clinic`, `order`, `checkout`, `airport`, `ticket`); each kiosk's screen box and colours are in the `LAYOUT` table in `machine-view.tsx`, in the 353x412 machine coordinate space.
- Languages: the 25 Muse Voice Transcribe languages live in `src/i18n/languages.ts`; app chrome strings in `src/i18n/strings.ts` (drafts, need native review); voice command words in `src/voice/commands.ts`. `?lang=<code>` on a guide deep link overrides the app language (used by `.maestro/09-voice-spanish.yaml`).
- Voice: `src/voice/match.ts` maps a transcript to a step action in code (labels first, then repeat/done/yes/no words); yes/no only count when an on-screen choice itself means yes/no, otherwise it answers "didn't catch that". In scenario mode the mic shows phrase chips (`testID="say-<i>"`) instead of recording.
- Spoken guidance: `src/voice/speaker.ts` plays a bundled natural-voice clip when one exists for the exact line, else falls back to `expo-speech`. Clips are generated by `npm run voice:generate` (`scripts/generate-voice.mts`), which shells out to edge-tts (`python3 -m pip install --user "edge-tts==7.3.1"`; older versions get HTTP 403 from Microsoft). Voices per scenario language are in the `VOICES` map (en-SG Luna, en-GB Sonia, fil-PH Blessica, id-ID Gadis), rate -8%. It writes `assets/voice/*.mp3` and `src/voice/clips.generated.ts`, caches by voice+rate+text, retries timeouts, and deletes unused clips. Re-run it after changing any `speech` or `result.title` text.
- Every Maestro flow starts with `subflows/close-open-guide.yaml`, because a deep link to the guide screen that's already open doesn't restart the scenario.
- If a Maestro flow fails on its first tap after a reload, it's a timing race: every flow waits with `waitForAnimationToEnd` after the first screen appears.
- E2E: Metro must be running, then `npm run e2e` (Maestro, flows in `.maestro/`, appId `host.exp.Exponent`). Screenshots go to `e2e-screenshots/` (gitignored). Buttons are targeted by `testID="action-<label>"`.
- Scenario data lives in `src/scenario/scenarios.ts`. Guidance comes through the `GuideSource` interface (`src/scenario/guide-source.ts`); scenario mode is the scripted source, the live camera + model pipeline must implement the same interface.
- `@expo/ui` `FieldGroup.SectionFooter` children must be wrapped in `@expo/ui` `Text`, or the app crashes.
- The simulator has no camera: scenario mode draws demo kiosks with `react-native-svg` in `src/components/machine-view.tsx`.
